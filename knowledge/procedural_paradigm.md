# The Procedural Paradigm — read this FIRST

This is the agent's constitution. It sits **above** the node crosswalks
(`houdini_to_geonodes.md`, `attribute_bridge.md`, `cop_to_compositor.md`). Those tell you
*which node*; this tells you *how to think*. If a task tempts you to hand-edit the scene,
re-read this before doing so.

---

## 1. Two paradigms, and why Blender is not Houdini

| | Imperative / destructive (Maya, **native Blender**) | Declarative / dataflow (Houdini, **Blender's GN/shader/compositor islands**) |
|---|---|---|
| The model is… | **the scene state** | **the network** |
| An operation… | **mutates state in place** (`bpy.ops.*`, edit-mode tools) | **derives a result** from inputs; nothing is mutated |
| Going back | **undo only** (history is a stack, not a definition) | change a parameter and **re-evaluate**; history is the graph itself |
| Authoring | you hand-model / hand-paint the result | you author **how to compute** the result |
| Reproducibility | a sequence of manual acts; not re-runnable | same inputs → same output, always |

Blender **bolted** a Houdini-style dataflow island (Geometry Nodes, shader nodes, compositor,
drivers) onto an app whose core is Maya-like: most operations are commands that fundamentally
change the scene, and only undo goes back. **The Houdini user does not model — they build
procedural networks.** Where a Maya user grabs the move tool, paints a texture, or poses a
joint, the Houdini user derives those changes from **information in the scene**: positions,
normals, curvature, measurements, proximity, volumes, custom math.

## 2. Why this is non-negotiable *here*

The goal is **3D synthetic data** — many varied samples generated by sweeping a parameter
space. That is *only* possible procedurally:

- **You cannot sweep a hand-edit.** A destructive tweak produces one artifact; it can't be
  re-parameterized, re-seeded, or batched.
- **Determinism is the product.** Same seed → same sample; new seed → controlled variation.
  Destructive history has no seed.
- So the procedural discipline is not aesthetic preference — it **is** the synthetic-data
  requirement. Every hand-edit is a bug against reproducibility.

## 3. Prime directive: **derive, don't set**

> Never assign a value you could **compute** from the scene.

"Move these points up" → *displace by a field* (noise × mask). "Paint it red here" → *color
driven by a measured attribute*. "Delete these faces" → *a selection field from a measured
condition* → Delete Geometry. The agent's default action is **author or extend a node graph**,
never issue a destructive scene mutation. Treat `bpy.ops` mesh/sculpt/paint edits as a **code
smell and a last resort** — allowed only for things with no procedural path, and then isolated
(see §6).

## 4. Where procedural thinking lives in Blender (and where it doesn't)

**Procedural islands — default to these:**
- **Geometry Nodes** (modifier) — procedural geometry, instancing, deformation, selection.
- **Shader nodes** — procedural appearance (bridged from GN via attributes).
- **Compositor nodes** — procedural image/passes (→ ground-truth labels).
- **Drivers & constraints** — parametric relationships between objects/values.

**Imperative rest — avoid for the deliverable:** edit-mode modeling, sculpt, texture/weight
paint, manual keys/poses. These mutate state and can't be swept. If you need what they produce
(e.g. a weight), **derive it as an attribute** instead (§5).

## 5. Scene-derived signals — the Houdini inputs, grounded in GN

These are what you *drive changes from* instead of hand-setting. All verified in the 5.2 schema:

| Signal (Houdini instinct) | Blender GN node(s) | Drives |
|---|---|---|
| position `@P` | `Position` (`GeometryNodeInputPosition`) | any spatial field |
| normal `@N` | `Normal` (`GeometryNodeInputNormal` → Normal, True Normal) | orientation, facing masks |
| curvature (`measure`) | mesh: `Edge Angle` (`GeometryNodeInputMeshEdgeAngle`); volume: `SDF Grid Mean Curvature` | wear on edges, erosion, masks |
| proximity / `xyzdist` / `minpos` | `Geometry Proximity` (`GeometryNodeProximity` → Position, Distance) | distance falloffs, contact effects |
| nearest element | `Index of Nearest`, `Sample Nearest` → `Sample Index` | transfer, clustering |
| measurements | `Attribute Statistic` (Mean/Sum/Min/Max/…), `Face Area`, `Bounding Box`, `Domain Size` | normalization, sizing, budgets |
| volume / SDF | `Mesh to Volume`, `Mesh to SDF Grid`, `Mesh to Density Grid`, `Sample Grid` | scatter-in-volume, thickness, erosion |
| scan / prefix-sum (`@ptnum`-ordered) | `Accumulate Field` (Leading/Trailing/Total) | cumulative length, indexing along curves |
| randomness (`rand`) | `Random Value` seeded by `Index`/`ID`/`Seed` | the variation axis of synthetic data |

The move is always the same: **read a signal → shape it with math (`Map Range`, `Compare`,
`Color Ramp`, curves) → feed it into a `Set*` / `Store Named Attribute` / selection.**

## 6. Non-destructive workflow rules (operational, for driving Blender)

1. **Author graphs, not edits.** Add/modify a GN modifier, material, or compositor tree.
   Don't enter edit mode to change the deliverable.
2. **Keep base geometry minimal.** Push shape/detail into the network, not into a hand-built
   mesh. The input mesh should be the *simplest thing the network needs*.
3. **Parameterize for sweeping.** Expose controls as the modifier's **Group Inputs** (or a
   controller empty / drivers) so a batch loop can vary them. A value you can't reach from code
   can't be swept.
4. **Isolate unavoidable destructive ops.** An import, a scan, a one-off cleanup — treat its
   result as a **clean input** feeding the procedural graph, never as an in-place mutation of
   the output.
5. **The network is the source of truth; undo is not your safety net.** You can always
   re-evaluate. Only **bake** (realize/apply) at the very end, for export.
6. **Verify across the parameter space, not one state.** "It looks right" for seed 0 is not
   done — evaluate several seeds and confirm the variation is valid and the labels stay exact.

## 7. Worked reframe

**Task: "make this rock look eroded."**
- *Maya/Blender reflex:* sculpt it by hand → one rock, not re-runnable, no labels.
- *Procedural:* displace by `noise × curvature(Edge Angle) × proximity-to-ground`, all
  seed-driven; store an `erosion` attribute for the shader and a `class_id` for masks.
  Result: **infinite eroded variants for free, each with aligned ground-truth** — i.e. a
  synthetic-data generator, not a model.

## 8. What this changes about the agent's loop

- Plan in **graphs and fields**, not commands. Ask "what signal drives this?" before "what
  tool changes this?"
- Prefer **graph diffs** (add nodes, rewire, set inputs) over scene mutation.
- The build→verify loop **evaluates the network across seeds/params**; a single rendered state
  is never sufficient proof.
- When you must fall back to `bpy.ops`, say so explicitly and quarantine it as an input.
